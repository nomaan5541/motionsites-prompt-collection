## 2. Scope & Threat Model

The **MotionSites Prompts Collection** consists of static Markdown files, JSON datasets, build scripts, and a client-side React/Vite web application. 

### In-Scope Areas:
- **Build Scripts & Tooling**: Node.js build scripts located in `scripts/` (e.g., `build-catalog.mjs`, `deduplicate_catalog.mjs`).
- **Web Application Client Code**: React components in `src/` (e.g., Cross-Site Scripting (XSS) risks in markdown/code rendering, injection risks in search inputs).
- **Static Asset Delivery**: Static assets served from `public/assets/`.

### Out-of-Scope Areas:
- Third-party AI model hallucinated code generated by external LLMs (Claude, ChatGPT, Cursor, etc.).
- Infrastructure security of third-party public CDNs hosting referenced video/image streams.

## 3. Reporting a Vulnerability

We appreciate the responsible security research community and encourage responsible disclosure of any potential vulnerabilities found within this codebase.

To report a vulnerability:
1. **GitHub Security Advisory**: Submit a private report via [GitHub Security Advisories](https://github.com/nomaan5541/motionsites-prompt-collection/security/advisories/new).
2. **Details to Include**:
   - Detailed description of the vulnerability and its potential impact.
   - Exact steps or minimal proof-of-concept (PoC) to reproduce the issue.
   - Any affected file paths, dependencies, or component names.
   - Recommended remediation or patch (if available).

---

## 4. Response & Remediation Lifecycle

Upon receipt of a valid security vulnerability report:
1. **Acknowledgment**: We aim to acknowledge receipt of the report within **24–48 hours**.
2. **Assessment & Verification**: The maintainer will investigate the issue and assess its severity using standard CVSS scoring.
3. **Remediation & Patching**: A patch will be authored, tested, and merged into `main`.
4. **Public Disclosure**: A public security advisory will be released once the patch is published.

---

## 5. Dependency Management & Hygiene

- All Node.js dependencies in `package.json` are pinned and audited using `npm audit`.
- Continuous integration workflows automatically scan for known CVEs across upstream packages.
